# ChromaSwarm

12-step multi-agent system that helps non-experts build professional frontend
pages one page at a time. Full spec: `docs/00_HANDOFF_CLAUDE.md` and
`docs/01..04_*.md`. Runtime knowledge base for agents: `knowledge-base/`.

## Layout

- `backend/` — Python 3.11+ orchestrator (`uv`, FastAPI + WebSocket, Pydantic, LangGraph, Anthropic SDK, Playwright).
  - `chromaswarm/state_machine/pipeline_state.py` — B1→B12 state, exit criteria, per-step tool grants.
  - `chromaswarm/state_machine/graph.py` — LangGraph B1–B7, one `interrupt()` per node pass, single router on `pipeline.step`; `PipelineRunner` is the WebSocket-facing API.
  - `chromaswarm/agents/consultant.py` — `ConsultantAgent` interface + `RuleBasedConsultant` (no-LLM baseline).
  - `chromaswarm/agents/llm.py` + `llm_consultant.py` — provider-neutral LLM layer, configured for **OpenRouter** (one key, any model). Three roles in `backend/.env`: `CHROMASWARM_LLM_MODEL` (text: B1–B7 interpretation, B7 feedback, B5 prose; default `qwen/qwen3.8-flash`), `_MODEL_CODE` (B9, default `qwen/qwen3-coder-next`), `_MODEL_VISION` (Clone mode from images; must accept images). The public OpenRouter catalogue is read once so each model gets the right request (reasoning off where allowed, lowest effort where mandatory; JSON mode only where supported, retried without it otherwise). `LLMConsultant` output is validated against closed value sets, prose is rejected unless every number is in `philosophy_facts`, and provider errors fall back to rules. `uv run python -m chromaswarm.agents.llm` validates the model IDs and the live connection. Model unset or placeholder key = rule-based.
  - `chromaswarm/agents/planner.py` — section blueprints, PRODUCT.md / PLAN.md renderers.
  - **Two modes, chosen at B1** (`BuildMode`):
    - *Creative* — real chat (`agents/chat.py`, WS message `{"type":"chat"}`): each message becomes `answer` (passed to the graph like a button, all validation applies), `ask` (Chroma replies from the session's DESIGN.md + standards ch.1–3; the pending question stays) or `revise` (B3 only: change an earlier pillar). Code-level limits in `chat.guard`: never approves B7, choice answers must be offered values, free-text answers keep the user's own words. No LLM → messages go straight through as answers.
    - *Clone* — B1 asks only the link (`clone_source`; a description is optional via the API). Without one, `raw_prompt` = "Dựng lại trang <host>" and the kind of site is guessed at B2 from the reference (`reader.guess_domain`: priced grid → ecommerce, else page-title words). Default = structure clone into a fill-in template; nobody is asked about ownership. "This site is mine" (copy its words and photos) is an opt-in behind a small "Chuyển trang của chính bạn sang Next.js?" link, then confirmed at B3 against the page's own name (declining drops the read content). A description asking for "100% / y hệt" gets one line in the B2 notice (layout and style are copied, the owner's words/photos/brand are not), never a question. B2 runs `clone/reader.py` (Playwright): the page's top-level sections classified onto buildable structures (in its own order), Style DNA → pillars, the reference's own fonts kept (`clone/fonts.py`: loaded from Google Fonts or Fontshare; a font with no Vietnamese glyphs gets a Vietnamese fallback of the same kind right after it in the font stack, and a note; a self-hosted / licensed font that no free host serves falls back to the preset), and — **only when the user confirmed ownership** — per-section text and image URLs (otherwise the JS returns no content). B3/B4 fill themselves from the reference (scope = description); B7 approval still required. Sitemap page slug `clone`; `planner.page_sections()` returns the reference's sections for it. Owned copy is mapped by section kind in `content.owned_clone_copy`. Pages are opened with `open_settled` (wait for `load`, ≤8s for network idle, then scroll through once for lazy / scroll-revealed content). The reader expands tall wrapper blocks and two-column layouts (content + sidebar: the side column's h1 box becomes the hero), keeps navigation, attaches loose headings to the next block in the same column, merges runs of picture-only blocks into one `gallery` section, counts any visual media (img/svg/video/canvas), and recognises feature showcases, testimonials (incl. CSS-drawn quotes / role lines / round-avatar cards), text-card rows, logo strips, list rows (entry + meta: posts with dates, work history) and closing CTAs. Tall `<header>`s (<360px) count as the navbar; fixed-position boxes narrower than half the page (promo widgets, chat bubbles) are skipped. A hero with no visual becomes `hero-text` (email signup when the reference had an input). The page's total content span is measured; under 1100px it is kept as `CloneSource.content_width` → `--container-max` (+ 2 gutters) in DESIGN.md / tokens.css. Sample copy is per domain and allocated page-wide (`content.copy_for`), so sections never repeat each other. **Designer passes (Clone):** B9 builds a wireframe (`app/wireframe.css`: every colour token at its own OKLCH lightness with no chroma, greyscale photos; content files hold `skeleton()` bars, no photos), then B10 runs one graph pass per stage — colour (wireframe.css emptied), content (real `content/*.ts` + `images.ts`) — before integrating (`pipeline.build_passes`). Heal loops skip the wireframe. **Effect check (Clone B2, its own graph pass after the structure read):** `clone/motion_check.py` opens the reference again (visible window with the Motion Inspector cursor unless `CHROMASWARM_HEADED=0`) and operates it: hidden-below-the-fold elements noted, parallax ratio, a slow scroll one viewport at a time timing each reveal frame by frame (start, duration, starting offset/opacity, easing, sibling stagger gap), marquee cycle, header blur, 16 real hovers (lift px, scale, zoom, duration, easing) → `MotionReport` (`clone.motion_report`, Studio card) and per-section `Section.motion` + `Section.motion_params`, which the Motion MCP `build_effect` takes as `distance_px / scale / cycle_s / stagger_ms / blur_px` + duration/easing. `Deps.motion_check` injects a fake; with a fake reader and no fake check the pass is skipped. The check also records what plays by itself on load (`motion.LOAD_JS`: intro animations with their keyframes, decorative loops), marquees running up/down as well as sideways (vertical ones are reported, not yet built), ignores anything inside an endless track for parallax / hover, caps a hover lift at 40px, and operates every control (`motion.click_controls`, own browser context): a link's destination is classified by path (same page / internal + role: sign-in, pricing, blog, legal / external host / new tab; internal pages fetched and rendered once to catch 404s, incl. SPA soft 404s), a button without a link is clicked in a fresh tab (found again by size + place) — navigates, opens a tab, a dialog, toggles (aria-expanded or its card's height), changes content, scrolls; identical rows reuse the first row's result; form submits are never pressed. **CLONE_BRIEF.md** (`clone/brief_doc.py`, written with ANALYSIS.md, `clone.brief`, shown in the Studio thread): the build team's preparation sheet for any link — the page and its concept (kind, which page, conversion goal from where the controls lead, persuasion flow), every section with its role, spacing per section (padding, side margins, gaps), type / colour roles / backgrounds the page paints itself (`reader.BACKGROUNDS_JS`: gradients, glows, glass, giant faint type), pictures (`reader.MEDIA_JS`: shown + file size, repeats, icons, logos — never URLs), every control (hover changes, click result / destination), effects, and what may / may not be cloned with its replacement. **Sketch step** (`clone/sketch.py`, B2 pass after the effect check, `Deps.sketch_check`, `clone.sketched` / `clone.sketch`): the page is drawn from what was read (grey boxes: text bars per line, pills, crossed picture boxes, card outlines, each section's measured background) and checked against a full-page screenshot in 24px cells — content cells (luminance varies) not covered by a read piece are reading gaps (a picture filling half its section and card frames do not count as covering). Gaps are measured again with every animation paused (`REGION_JS`; e.g. a moving column of cards), the pieces join their section (`add_found`, measured sections' `layout` updated), coverage is computed again; reference screenshot | sketch per screen → `artifacts/sketch/ref-NN.jpg` (`GET /sessions/{id}/sketch/{file}`, Studio sketch card). What is still not read after that is cropped and named by the vision model (`_MODEL_VISION`, must accept images; `sketch.parse_vision`: closed kinds image/card/button/text/heading/logo/icon/input/video/mixed, count, layout row/column/grid) and laid out on its grid as pieces of that kind; without a working vision model a large gap keeps its place as one block. Then the analysis, CloneSpec and brief are written from the completed reading. B10, before the colour pass: `runtime.sketch_check` sketches the wireframe the same way, scores how much of each reference section's sketched area the rebuild covers (`compare_sketches`) → `clone.sketch_built`, `built-NN.jpg` pairs, B10 notice; and, since the DOM alone misses what CSS / canvas / clipping change, the wireframe's full-page screenshot is compared with the reference's (B2 `reference.jpg`) cell by cell per section (`compare_pixels`, each section aligned at its own top) → `pixel_score`, red frames over what the rebuild lacks, `shot-NN.jpg` pairs. **CloneSpec** (`clone/spec.py`, `clone.spec`, built at B2 right before the brief, which renders it as section 8): every item of the reference — sections, pictures / icons / logos, words, testimonials, controls, effects, painted backgrounds, fonts — gets `copy` / `replace` / `skip` / `todo` with why and its replacement, and the build **reads it** (`graph.apply_spec` → `Section.links`, `Section.paint`, `Section.motion`): measured links / buttons take the spec's href (`measured._Render.href`, matched by place + size: in-page links → `#<rebuilt section>`, the user's own pages → named placeholders `#dang-ky` / `#bang-gia` / `#blog` / `#phap-ly` editable in `content/`, external / dead / broken → `#`); big gradients and glows are redrawn as decorative layers (`measured.paint_layers`: aria-hidden, behind the content, with the reference's intro keyframes when a load animation played on them); effects marked `copy` go to the Motion MCP (an intro animation not played by a layer → `reveal` at the measured duration / distance); vertical marquees, menus / dialogs and decorative loops are `todo` / `skip`. At B7 the user changes decisions (`{"spec": {"section:<id>": "skip"}}`, Studio: the section checkboxes under the brief): `planner.page_sections` drops skipped sections, PLAN.md and the brief are rewritten, the 1:1 acceptance compares built sections only. Rows that open are an FAQ (`faq`) only when their labels end with “?” (`questions`, a count); otherwise `feature-accordion`. A 0px `<header>` holding a fixed bar counts as that bar (the bar with the navigation, not a promo strip above it); a fixed block's top is its window place. **Motion (Clone):** `clone/motion.py` holds the probes the effect check runs — below-fold elements hidden before the settle scroll and visible after (scroll-reveal; 3+ siblings = stagger-cards), elements drifting against the scroll (parallax), infinite sideways animations / moving wide tracks (marquee), up to 16 cards/rows/links/buttons hovered for real (hover-lift, hover-zoom, hover-image, underline-link), sticky/blurred header, smooth scroll (Lenis), libraries, and what CSS cannot rebuild (custom cursor, canvas/WebGL → listed as limits). Effects land in `Section.motion` and are built by the Motion MCP server (`build_effect`, CSS only, page-scoped, reduced-motion safe); logo strips get a duplicated marquee track, list rows a decorative hover preview. **Picture/text-led references (Clone B4):** the reader measures `media_share` (visible media area / page area); a structure clone of a portfolio, a page ≥25% pictures or ≥6 picture slots gets a `clone_content` question (`clone/content_slots.py`): a warning that the owner's photos and words are not copied so those parts will look different, the picture slots in page order, and fields for name / headline / intro / project titles / email. Photos arrive as data URLs (downscaled in the Studio), are saved to `workspaces/<session>/uploads/` (image types only, ≤8MB, ≤24) and copied to the app's `public/images/`; `content.user_clone_content` puts them and the words in place of placeholders and samples. Skipping keeps the template samples. **Preview:** `GET /clone/preview?url=` (first-screen screenshot + title, `clone/preview.py`) shown under the link field before reading. The page language follows the reference (`developer/i18n.py`: `<html lang>`, English copy pools + UI strings; other languages build in English). **Components (Clone):** `clone/components.py` reads every page's smallest pieces (heading / text / link / button / image / input / card: box + computed style, never text or URLs) — the reference per reader block at B2 (`clone.components`, `clone.boxes` per section), the rebuild per `[data-swarm-section]` (`data-cs-comp` attributes). `match()` pairs same-kind components by relative position; `section_score()` = 40% components present · 30% placement (IoU) · 20% style · 10% section height; `tune_rules()` writes the reference's font size / weight / tracking / leading / case, radii, button padding (only larger: tap targets) and card shadow/border into `app/match.css` (desktop ≥1200px only, before heal.css; body text never under 16px). **Measured sections (Clone, structure clones):** a section whose reference components are usable (2–48 pieces) and whose structure is not behaviour-bound (`measured.TEMPLATE_ONLY`: header, tabs, accordion, scroller, list rows, logo strip…) gets `Section.layout` + `layout_box` at B2 and is rendered by `developer/measured.py` instead of its template: `clone/layout.py` puts pieces inside the card that holds them (≥85% inside; a frame-filling picture counts), then a recursive XY-cut splits siblings into rows / columns along empty bands; text over a picture becomes a `layer` (pictures behind at their measured place, the rest flows on top); anything else overlapping falls back to reading order. Desktop (≥1200px, inline `<style>` in the component): each node's left offset and width as % of its parent, vertical gaps in px, the reference's top/bottom space and content span, measured type (weights snapped to 400/600, §2.2), radii, card shadow/border; tablet: columns share a row; phone: a stack on the design system's scale. Words: the page's sample copy (or the user's) cut to the length the reference showed in that box, kept in `content/`; pictures: `Art` at the measured aspect ratio; one filled button per section; controls get `data-swarm-id` `<section>-btn|link|input-<n>` (also listed in PLAN.md). Reference measuring (per block, scrolled into view): transparent hover-only elements, slides clipped by their frame (>70%) and decorative aria-hidden media are skipped; a box-less (`display: contents`) wrapper's opacity is ignored; aria-hidden text and big words hidden in the DOM but painted by a canvas over them (WebGL type) count; a heading / link / button whose words sit side by side with a gap, or a huge line with a small caption, is measured piece by piece; text pieces carry their character count and real run width/offset (never the words). Rendering: the reference's own colours at every width (text incl. transparency, button fills, card fills, each section's sampled background; a section painted opposite to the page is an `s-band`), its own weights and sizes and its button sizes on desktop (phones keep 48px tap targets); one-line labels stay one line, centred copy stays centred, a ≥160px line is the brand wordmark; HTML product mockups (a frame of 8+ tiny labels, no heading) are one picture; up to 240 pieces per section; rows that outgrow the page wrap instead of pushing controls off it; an accordion keeps its measured look and its rows open and close (`<details>`). **Clone QA profile:** `run_master_qa(clone=True)` (set when the runtime has reference components) waives the house-style rules a reference may break by design (`master.CLONE_WAIVED`: ≤2 weights, triple cards, centred ≥3 lines, one filled CTA per section, long-text size/leading); contrast, control borders, focus, hover, overflow, collisions, phone tap targets and broken images still apply. **Factory (Clone B9):** in `check_section`, after the Design pass, a section cursor splits into crews (chữ / nút & ô nhập / ảnh & thẻ) and one cursor per component (`SwarmOverlay.spawn/crew/merge`), each marking its component ✓ or with its difference; the crews' tuning goes into match.css, the section is measured again, the workers merge back (`PipelineState.factory_log`). **1:1 acceptance (Clone B11, after QA passes, own pass):** `runtime.compare()` opens the reference link in a second window, re-measures both pages, the Master cursor visits every pair in both windows (red flag where they differ), photographs each section of both (`artifacts/compare/<id>-ref|clone.jpg`, served by `GET /sessions/{id}/compare/{file}`, side by side in the Studio), checks the rebuild's effects with the same probes, tunes match.css; if anything was tuned QA runs again, then another comparison (max 2 rounds) → `clone_compare`, `COMPARE.md`. Text and photos are never compared (a structure clone does not copy them), so 100% is reachable only for layout and style. **Clone DESIGN.md, extracted backwards** (`clone/design_extract.py`, B2 → `clone.design` / `artifacts/design.json`; at B5 a Clone's DESIGN.md is its rendering, with the engine tokens as a technical appendix): tokens read off the reference with their use counts (colours by role: section backgrounds by area, text levels by characters, accents from button fills, card surfaces; text styles by size + weight with their usual leading / tracking / case, named display / h1… / body / caption by what they are mostly used for; spacing scale from padding and gaps; radii; content width; motion), a component library (button / card / image / link variants with size, fill, ink, type, radius, padding, hover) and a spec per section (box, background token, padding, margins, gaps, layout tree, every component with place, size and the tokens / variant it uses, hover / click, effects, painted backgrounds). **Master QA verdict** (`clone/conformance.py` + `clone/verdict.py`, end of the 1:1 pass): the finished page is measured (`runtime.measure_built`) and checked against design.json item by item with unnoticeable tolerances — section present / height / padding, each component present (paired by kind + relative place) / x / y / width / height (non-text) / text size and weight / ink / fill / radius, listed effects present → `clone_verdict` (passed / total, per section with every differing item in words), `CLONE_RESULT.md`, B11 notice, B12 card, Studio verdict panel. Success = QA passed and every item matches; close = QA passed and ≥ 90%; the sketch / screenshot (`sketch_final`, `fbuilt-` / `fshot-`), 1:1 and fidelity scores are indicators only. Factory worker cursors stay pinned to their component while the page scrolls (hidden off screen, never parked at an edge). **Clone templates (owned clones / sections with a design spec):** `developer/clone_templates.py` recognises each section by meaning (`kind_of`: announcement, nav, hero, cards, features, feature-accordion, faq, testimonials, footer) and renders a designed template whose numbers come from the extracted design.json (type tokens, button / card variants, padding, content width, row heights, gaps) and whose words / pictures are the owner's (matched by place; a heading keeps only text of its own size); measured placement is the fallback. Announcement bar dismissible (remembered) and pinned above the sticky nav (`--cs-announce-h`); nav language switch = pill + menu; buttons get an arrow when the reference button is wider than its words; vertical marquee hero / quote wall (duplicate copies `aria-hidden`); footer's giant faint wordmark drawn by CSS (`data-word`). QA probe: collisions use the clipped (shown) box, the inline-link rule only counts links beside other words. **History (Clone only, Supabase):** `clone/history.py` writes Clone sessions to Supabase through PostgREST with the service-role key (`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` in `backend/.env`; empty = disabled, nothing changes): `clone_sessions` (full `PipelineState` + url/title/domain/step/status/fidelity), `clone_messages` (the user's answers — uploads counted, never stored — Chroma's notices and questions), `clone_events` (step changes, notices, effect report, handover results). Tables in `supabase/migrations/20261120000000_clone_history.sql` (RLS on, no policies: only the backend reads them). Hooked in `main.resume` (answer before, snapshot after, every progress notice) — Creative sessions are never written. **Graph state (Clone threads):** the graph's checkpointer is `clone/checkpoints.SupabaseCloneSaver` (set in `main.py`; `graph.py` unchanged) — an `InMemorySaver` that mirrors every new checkpoint of a Clone thread (latest checkpoint per namespace + its channel blobs + pending writes, serialized with the graph's `SERDE`) to `clone_graph_checkpoints` in the background, and loads a thread missing from memory back from it; Creative threads stay in memory only. After a backend restart a Clone session continues exactly where it waited (`main.restore_clone`; only a build cut off mid-run — B8–B11 with no question pending — goes back to the B7 approval, its dev server and browser being gone). `GET /clone/sessions`, `GET /clone/sessions/{id}/messages`; Studio `clone-history.tsx` (`useCloneSessions`) feeds the history sidebar and redraws a reopened session's conversation. **Fidelity** (`clone/fidelity.py`): both pages read with the same reader + Style DNA, scored 0–100 (structure 35 incl. half credit for the right kind family, height proportions 25, length 10, content width 10, colours + base font 20); B11 in Clone mode writes `FIDELITY.md` and `clone_fidelity`. **Suite** (`clone/suite.py` + `suite.json`, 10 reference sites): `uv run python -m chromaswarm.clone.suite` checks reader output against the baseline (~10s/site); `--build` rebuilds each site rule-based/headless and scores it (`workspaces/_suite/<site>/compare.jpg`, `report.md`); `--update` accepts results as the new baseline. A run fails on a changed section sequence or a fidelity drop > 5 points — run it before committing reader changes.

## Decisions (do not re-litigate)

1. Orchestrator is Python, not TypeScript (doc 04 Part 4 is superseded).
2. Gates are enforced in code: B1–B7 agents get no code-writing tools (`ALLOWED_TOOLS`); Clarity Score = filled pillars / 5; B7 passes only via an explicit user `approve_plan`.
3. B8/B9 run pipelined per section (Dev writes section N while Design measures N−1), not truly simultaneously. B8 = Design installs tokens only; B9 grants both departments' tools because they work pipelined.
4. Design-department changes are written to the workspace token file, never only applied via CSSOM.
5. B11 self-healing loop is capped at `MAX_HEAL_ITERATIONS = 3`, then escalates to the user.
6. Swarm Rebuild is inspiration only; the overlay is written from scratch.
7. Every number in DESIGN.md comes from the engines; an LLM may only write the philosophy prose and pick presets. Clone mode: DESIGN.md's numbers are measured on the reference (code, never an LLM) — same principle, different source.
8. Unclear answers are re-asked (`interpret()` returns None) — never filled in by the agent. Answers already given in the first prompt are taken (with a verified quote, `agents/brief.py`) and not asked again; nothing is inferred from the product type.
9. Deviations from FRONTEND_STANDARDS.md, chosen to keep APCA / 8pt checks passing: dark-mode text-secondary 78% and text-muted 68% (spec: 72% / 52%); dense section padding 48px (spec: 40–56px, off-grid); mobile type ratio = 1 + 0.6·(r−1). Fonts (presets, i.e. Creative mode; Clone keeps the reference's fonts): Instrument Serif → Playfair Display (editorial-luxury), Outfit/DM Sans → Fraunces/Be Vietnam Pro (warm-organic; serif heading for contrast), because the originals have no Vietnamese subset; `VIETNAMESE_FONTS` + a test guard every preset font.
10. Studio UI itself follows `FRONTEND_STANDARDS.md` (OKLCH tokens in `globals.css`, 8pt spacing, no AI-slop patterns).
11. Anti-cloning (standards §2.4) applies to **Creative mode only**. **Clone mode** (§2.5) may rebuild the reference's whole look identically — layout, colours, typography (its own fonts), spacing — but never its text or images (copyright): structure clone by default, the user's own text/images in `content/`; **Clone 100%** (text, brand, logo, images too) only for the user's own site, opted into behind a small link and confirmed against the page's name at B3. Ownership is never inferred, and without the tick the reader returns no content at all. Clone pages still pass B7 approval and B11 with the Clone QA profile (accessibility rules kept, house-style rules waived — see Clone QA profile).
