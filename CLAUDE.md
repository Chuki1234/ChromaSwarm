# ChromaSwarm

12-step multi-agent system that helps non-experts build professional frontend
pages one page at a time. Full spec: `docs/00_HANDOFF_CLAUDE.md` and
`docs/01..04_*.md`. Runtime knowledge base for agents: `knowledge-base/`.

## Layout

- `backend/` — Python 3.11+ orchestrator (`uv`, FastAPI + WebSocket, Pydantic, LangGraph, Anthropic SDK, Playwright).
  - `chromaswarm/state_machine/pipeline_state.py` — B1→B12 state, exit criteria, per-step tool grants.
  - `chromaswarm/state_machine/graph.py` — LangGraph B1–B7, one `interrupt()` per node pass, single router on `pipeline.step`; `PipelineRunner` is the WebSocket-facing API.
  - `chromaswarm/agents/consultant.py` — `ConsultantAgent` interface + `RuleBasedConsultant` (no-LLM baseline).
  - `chromaswarm/agents/llm.py` + `llm_consultant.py` — provider-neutral LLM layer, configured for **OpenRouter** (one key, any model). Three roles in `backend/.env`: `CHROMASWARM_LLM_MODEL` (text: B1–B7 interpretation, B7 feedback, B5 prose; default `qwen/qwen3.8-flash`), `_MODEL_CODE` (B9, default `qwen/qwen3-coder-next`), `_MODEL_VISION` (Clone mode from images; must accept images). The public OpenRouter catalogue is read once so each model gets the right request (reasoning off where allowed, lowest effort where mandatory; JSON mode only where supported, retried without it otherwise). `LLMConsultant` output is validated against closed value sets, prose is rejected unless every number is in `philosophy_facts`, and provider errors fall back to rules. `uv run python -m chromaswarm.agents.llm` validates the model IDs and the live connection. Model unset or placeholder key = rule-based.
  - `chromaswarm/agents/planner.py` — section blueprints, PRODUCT.md / PLAN.md renderers.
  - **Two modes, chosen at B1** (`BuildMode`):
    - *Creative* — real chat (`agents/chat.py`, WS message `{"type":"chat"}`): each message becomes `answer` (passed to the graph like a button, all validation applies), `ask` (Chroma replies from the session's DESIGN.md + standards ch.1–3; the pending question stays) or `revise` (B3 only: change an earlier pillar). Code-level limits in `chat.guard`: never approves B7, choice answers must be offered values, free-text answers keep the user's own words. No LLM → messages go straight through as answers.
    - *Clone* — B1 asks only the link (`clone_source`; a description is optional via the API). Without one, `raw_prompt` = "Dựng lại trang <host>" and the kind of site is guessed at B2 from the reference (`reader.guess_domain`: priced grid → ecommerce, else page-title words). Default = structure clone into a fill-in template; nobody is asked about ownership. "This site is mine" (copy its words and photos) is an opt-in behind a small "Chuyển trang của chính bạn sang Next.js?" link, then confirmed at B3 against the page's own name (declining drops the read content). A description asking for "100% / y hệt" gets one line in the B2 notice (layout and style are copied, the owner's words/photos/brand are not), never a question. B2 runs `clone/reader.py` (Playwright): the page's top-level sections classified onto buildable structures (in its own order), Style DNA → pillars, the reference's own fonts kept (`clone/fonts.py`: loaded from Google Fonts or Fontshare; a font with no Vietnamese glyphs gets a Vietnamese fallback of the same kind right after it in the font stack, and a note; a self-hosted / licensed font that no free host serves falls back to the preset), and — **only when the user confirmed ownership** — per-section text and image URLs (otherwise the JS returns no content). B3/B4 fill themselves from the reference (scope = description); B7 approval still required. Sitemap page slug `clone`; `planner.page_sections()` returns the reference's sections for it. Owned copy is mapped by section kind in `content.owned_clone_copy`. Pages are opened with `open_settled` (wait for `load`, ≤8s for network idle, then scroll through once for lazy / scroll-revealed content). The reader expands tall wrapper blocks and two-column layouts (content + sidebar: the side column's h1 box becomes the hero), keeps navigation, attaches loose headings to the next block in the same column, merges runs of picture-only blocks into one `gallery` section, counts any visual media (img/svg/video/canvas), and recognises feature showcases, testimonials (incl. CSS-drawn quotes / role lines / round-avatar cards), text-card rows, logo strips, list rows (entry + meta: posts with dates, work history) and closing CTAs. Tall `<header>`s (<360px) count as the navbar; fixed-position boxes narrower than half the page (promo widgets, chat bubbles) are skipped. A hero with no visual becomes `hero-text` (email signup when the reference had an input). The page's total content span is measured; under 1100px it is kept as `CloneSource.content_width` → `--container-max` (+ 2 gutters) in DESIGN.md / tokens.css. Sample copy is per domain and allocated page-wide (`content.copy_for`), so sections never repeat each other. **Fidelity** (`clone/fidelity.py`): both pages read with the same reader + Style DNA, scored 0–100 (structure 35 incl. half credit for the right kind family, height proportions 25, length 10, content width 10, colours + base font 20); B11 in Clone mode writes `FIDELITY.md` and `clone_fidelity`. **Suite** (`clone/suite.py` + `suite.json`, 10 reference sites): `uv run python -m chromaswarm.clone.suite` checks reader output against the baseline (~10s/site); `--build` rebuilds each site rule-based/headless and scores it (`workspaces/_suite/<site>/compare.jpg`, `report.md`); `--update` accepts results as the new baseline. A run fails on a changed section sequence or a fidelity drop > 5 points — run it before committing reader changes.
  - `chromaswarm/engines/` — deterministic, no LLM: `color` (OKLCH, WCAG, APCA), `palette` (60-30-10; `border-subtle` decorative vs `border-strong` ≥3:1 for controls; `accent-ink` = accent readable as text for links/secondary buttons), `typography`, `spacing` (8pt), `presets`, `style_dna` (analysis), `design_spec` (DESIGN.md + tokens.css incl. 3 shadow levels).
  - `chromaswarm/playwright_engine/style_dna_scraper.py` — returns aggregate style stats only (no DOM/text).
  - `chromaswarm/playwright_engine/swarm_overlay.js` — injected overlay (shadow DOM, `pointer-events:none`, re-attaches after re-renders): 4 Design cursors + rulers/box-model bands, 2.2x Master cursor + HUD + red flags, `handover()` removes it. It only reads the DOM.
  - `chromaswarm/playwright_engine/swarm.py` — `SwarmOverlay` (Python driver, event sink for streaming) and `design_pass()`: per section Layout → Color → Typography; verdicts (8pt grid, mobile gutter ≥16px, WCAG/APCA, 45–72ch, type scale) computed in Python with the engines. Demo: `uv run python -m chromaswarm.playwright_engine.demo [url]` (fixture page with 3 seeded defects).
  - `chromaswarm/developer/photos.py` — topic-matched free-license Unsplash photos (ids checked by eye) when the user has none; accent-folded matching only for long keywords (short ones collide: trà/kiểm tra). `Art` falls back to neutral tonal SVG on error; `CHROMASWARM_STOCK_PHOTOS=0` disables.
  - Surface material (`presets.Surface`: flat / liquid-glass / clay / brutal): optional `Pillars.surface`, asked right after the theme (skipped when the first message names one, changeable in B7 feedback), never counted in the Clarity Score. Overrides radii + the 3 shadow tokens (`design_spec`), and `developer/surfaces.py` writes `app/surface.css` (imported after base.css, before heal.css). Glass glows live on a fixed `body::before` so QA can still measure text contrast. Neumorphism and aurora gradients are excluded on purpose (standards §2.6.4).
  - `chromaswarm/agents/brief.py` — prompt reader (`Deps.brief_reader`), read once at B2 for **every** Creative prompt: a complete prompt is never asked again, a partial one only for what is missing. Accuracy: each pillar / page / audience / CTA is kept only if the model quotes the words that state it and the quote is really in the prompt (`in_prompt`, accent-folded); the CTA must be the user's literal words; a tone quote must name a tone ("tối giản" ≠ dark); hex only if literal, colour names only after "màu …" ("cà phê nâu" is a drink); fonts only with a Vietnamese subset. Exact patterns for page ("landing page"), photo source ("Unsplash" → B4 skipped), CTA. B2 skips the page question when named; B3 pre-fills, lists what is still missing, never asks the material when the style was given, keeps half a scope answer in `scope_draft` and asks only the other half; a tone-only colour answer keeps the colour named in the prompt. The user's section order (`planner.sections_from_brief`: announcement-bar, usp-strip, grid-4 with category tabs, picker-recommend…) is used only when they listed ≥3 blocks. A user-given accent keeps its chroma (`palette exact`) and drives the buttons (`brand_actions`).
  - `chromaswarm/developer/copywriter.py` — LLM copywriter (text role, `Deps.copywriter`): once per page in B9 (keyed by prompt/scope/feedback → `PipelineState.page_copy`), never for an owned Clone. Validated in code: same shape as the rule copy, length limits, banned generic phrases, no invented price/time/percent (number + unit must be in the facts); prices and the facts strip stay the rules'. Rejected twice → rule copy. No sample-content disclaimer on the page (it lives in PRODUCT.md / handover).
  - Action colour: `--action*` tokens (`design_spec.action_tokens`) = accent for tech/bold presets, near-black for luxury/warm; buttons and links use them, never `--accent` directly. Product cards are borderless (`.product`), one image height per row.
  - `chromaswarm/developer/` — B9 Developer (rule-based baseline): `nextjs.py` renders one TSX component per PLAN.md section structure (real interactions, `data-swarm-*` on every control, styling only via tokens) + workspace scaffold; `content.py` builds page copy from the user's answers/assets; `workspace.py` writes files tool-gated per step and runs `next dev` (port 3001+, own process group).
  - `chromaswarm/design/dept.py` — B8 Design repairs: contrast → shift the colour token's OKLCH lightness; off-grid spacing → snap the spacing token. Written to the workspace `app/tokens.css` (decision 4); the rest goes to `open_findings`.
  - `chromaswarm/build/runtime.py` — `LocalBuildRuntime` owns per-session workspace, dev server, Playwright page + overlay (not checkpointed). B8 installs tokens; each B9 graph tick = Dev writes section N ∥ Design checks N−1; B10 reloads, checks section order + console errors. `CHROMASWARM_BUILD=0` stops after B7, `CHROMASWARM_HEADED=0` hides the browser.
  - `chromaswarm/qa/` — B11 Master QA: `qa_probe.js` (read-only DOM measurements) + `master.py` (4 tests of standards ch.5: interaction sweep incl. hover/click/console/focus-visible, scroll & sticky, 1440/1024/768/375 overflow/collision/margins/tap targets ≥48px + ≥8px apart in a row, DESIGN.md fonts + contrast + automatable anti-slop rules + measurable chapter 6–7 rules: control borders, placeholder-only inputs, red asterisks, inline-link underline, unexplained disabled controls, generic labels, long-text size/leading/justify, ≤2 font weights, number separators). Each failure carries a `heal` CSS rule (Developer → `app/heal.css` on the next B9) or a colour reading (Design → `tokens.css`). Loop: FAIL → B8 (tokens kept) → B11, max 3; nothing patchable → escalate at once. Fixture with one seeded defect per rule: `qa/fixtures/qa_defects.html`.
  - `chromaswarm/qa/critic.py` — design critic: vision model (`_MODEL_VISION`) grades screenshots (desktop slices + mobile, clean tab without the overlay) on 8 weighted dimensions; overall computed in code. Runs in B11 after QA passes, non-blocking → `design_score`, `design_critique`, `CRITIQUE.md`, Studio QA panel. Benchmark any URL: `uv run python -m chromaswarm.qa.critic URL...` (validated 2026-11-14: Linear 9.1, Chamberlain 8.1 > our pages). Hero repertoire: `planner.hero_structure` (split / editorial / overlay / centered); content sections alternate `surface="alt"` bands.
  - `chromaswarm/mcp_motion/` — B8.1: a real MCP server (`server.py`, stdio, tools `list_effects` / `build_effect`) returning dependency-free CSS effects (reveal, scroll-driven parallax, stagger; reduced-motion safe, page-scoped); `client.py` is what the Motion agent uses. `CHROMASWARM_MOTION_MCP="<cmd>"` swaps in an external server with the same tool contract. Motion failures never stop a build.
  - B12 (`graph.b12`): overlay removed + in-page handover bar (exposed binding → `main.browser_choice`), Studio card: next sitemap page (→ B6, DESIGN.md + tokens kept, new route `/<slug>`, earlier pages' headers re-rendered with the new link), refine with feedback (→ B5, re-approval at B7), or finish. One lock per session serialises Studio and browser answers.
  - Generated artifacts go to `workspaces/<session>/artifacts/`, the target app to `workspaces/<session>/app/`.
- `studio/` — Next.js 16 control UI, chat-first (like ChatGPT): empty screen = one prompt box + Creative/Clone switch + example prompts (a typed prompt picks Creative and is sent when Chroma asks for it); then one conversation thread (user bubbles right, Chroma left; each pipeline question is a Chroma message with its options / form / B7 docs / build panel inline), a composer pinned at the bottom (Enter sends, Shift+Enter new line), steps + progress in a side panel (drawer on mobile). Port 3000.
- `workspaces/<project>/` — generated target apps (port 3001+). Never generated inside `studio/`.
- `knowledge-base/` — `FRONTEND_STANDARDS.md` (kept identical to `docs/03_FRONTEND_STANDARDS.md`; code cites its section numbers, so never renumber) + `PRACTICAL_UI_NOTES.md` (paraphrased notes from *Practical UI*, the source of chapters 6–7) + templates for DESIGN/PRODUCT/PLAN.md.

## Commands

```bash
cd backend && uv run pytest -q   # offline; needs `uv run playwright install chromium` once
cd backend && uv run python -m chromaswarm.clone.suite [--build] [--only a,b] [--update]   # Clone regression suite (live sites)
CHROMASWARM_E2E=1 uv run pytest -q tests/test_build.py   # + real npm/next dev/Chromium build (~35s)
cp backend/.env.example backend/.env   # then set the LLM key, or empty the model for rule-based
cd backend && uv run uvicorn chromaswarm.main:app --port 8100 --reload
cd studio && npm run dev
```

The backend uses port **8100** (8000 is taken by another local service).

## Decisions (do not re-litigate)

1. Orchestrator is Python, not TypeScript (doc 04 Part 4 is superseded).
2. Gates are enforced in code: B1–B7 agents get no code-writing tools (`ALLOWED_TOOLS`); Clarity Score = filled pillars / 5; B7 passes only via an explicit user `approve_plan`.
3. B8/B9 run pipelined per section (Dev writes section N while Design measures N−1), not truly simultaneously. B8 = Design installs tokens only; B9 grants both departments' tools because they work pipelined.
4. Design-department changes are written to the workspace token file, never only applied via CSSOM.
5. B11 self-healing loop is capped at `MAX_HEAL_ITERATIONS = 3`, then escalates to the user.
6. Swarm Rebuild is inspiration only; the overlay is written from scratch.
7. Every number in DESIGN.md comes from the engines; an LLM may only write the philosophy prose and pick presets.
8. Unclear answers are re-asked (`interpret()` returns None) — never filled in by the agent. Answers already given in the first prompt are taken (with a verified quote, `agents/brief.py`) and not asked again; nothing is inferred from the product type.
9. Deviations from FRONTEND_STANDARDS.md, chosen to keep APCA / 8pt checks passing: dark-mode text-secondary 78% and text-muted 68% (spec: 72% / 52%); dense section padding 48px (spec: 40–56px, off-grid); mobile type ratio = 1 + 0.6·(r−1). Fonts (presets, i.e. Creative mode; Clone keeps the reference's fonts): Instrument Serif → Playfair Display (editorial-luxury), Outfit/DM Sans → Fraunces/Be Vietnam Pro (warm-organic; serif heading for contrast), because the originals have no Vietnamese subset; `VIETNAMESE_FONTS` + a test guard every preset font.
10. Studio UI itself follows `FRONTEND_STANDARDS.md` (OKLCH tokens in `globals.css`, 8pt spacing, no AI-slop patterns).
11. Anti-cloning (standards §2.4) applies to **Creative mode only**. **Clone mode** (§2.5) may rebuild the reference's whole look identically — layout, colours, typography (its own fonts), spacing — but never its text or images (copyright): structure clone by default, the user's own text/images in `content/`; **Clone 100%** (text, brand, logo, images too) only for the user's own site, opted into behind a small link and confirmed against the page's name at B3. Ownership is never inferred, and without the tick the reader returns no content at all. Clone pages still pass B7 approval, the chapter-2 checks and B11.
